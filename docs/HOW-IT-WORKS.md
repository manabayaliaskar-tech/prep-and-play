# Как устроен Prep&Play — объяснение без программистского опыта

Прочитайте всей командой — тогда вы спокойно ответите на любой вопрос жюри.

## 1. Из чего состоит сайт

- **HTML** (`index.html`) — скелет страницы.
- **CSS** (`styles/main.css`) — внешний вид: цвета, кнопки, анимации.
- **JavaScript** (папка `src/`) — «мозг»: что происходит при нажатии.

Сервер и база данных не нужны: браузер всё делает сам, а прогресс хранится в памяти браузера (localStorage).
Поэтому сайт можно бесплатно разместить на GitHub Pages.

## 2. Три слоя проекта

1. **Контент** (`src/content/`) — задания. Он ничего не знает о кнопках и экранах.
   - `rw/` — 104 задания Reading & Writing, написанные вручную. У каждого: текст, вопрос,
     4 варианта и объяснение на трёх языках.
   - `math/` — **генераторы**: это не готовые задачи, а «рецепты». Генератор берёт случайные числа
     и собирает из них задачу, правильный ответ, ловушки (типичные ошибки) и пошаговое решение.
     Поэтому задачи никогда не заканчиваются.
2. **Движок** (`src/engine/`) — правила игры: проверка ответа, опыт, комбо, жизни, урон боссу, звёзды,
   прогноз балла.
3. **Интерфейс** (`src/ui/`, `src/screens/`) — экраны и кнопки.

Зачем так делить? Если поменять дизайн — задания не сломаются. А правила игры и задания можно проверить
автоматическими тестами без браузера.

## 3. «Зерно» — секрет дуэлей и задания дня

Компьютер не умеет выбирать «по-настоящему случайно» — он считает случайные числа по формуле,
начиная с какого-то стартового числа. Это число называется **зерно (seed)**.
Одинаковое зерно → одинаковая последовательность чисел → **одинаковые задания**.

- **Дуэль:** в ссылку записываются зерно, имя и результат. Друг открывает ссылку → из того же зерна
  получаются те же задания → результаты можно честно сравнить. Сервер не нужен!
- **Задание дня:** зерно получается из сегодняшней даты, поэтому у всех игроков задания одинаковые,
  а завтра будут новые.

## 4. Пробный экзамен как на настоящем SAT

На цифровом SAT каждый раздел — 2 модуля. Если хорошо решил первый (у нас — 60% и больше),
второй модуль будет сложнее, и максимальный балл выше. Если хуже — второй модуль легче.
Мы повторили эту логику. Балл считается с учётом сложности заданий (сложные «весят» больше).
Это примерная оценка — на сайте так и написано.

## 5. Как проверяются ответы с вводом

На SAT в части задач нет вариантов — нужно ввести число. Правила: можно вводить дробь (3/4)
или десятичную (0.75); если дробь бесконечная (2/3), нужно минимум 3 знака: .666 или .667 —
верно, а .66 — нет. Наша проверка работает так же.

## 6. Тесты и CI/CD

- **Тесты** (`tests/`) — программы, которые проверяют программу. Например, каждый из 20 генераторов
  создаёт сотни задач на каждой сложности, и тест проверяет, что нигде нет ошибок, у вариантов нет повторов,
  а решение есть на всех трёх языках. Ещё тест проверяет, что каждая надпись интерфейса переведена.
  Запуск: `npm test`.
- **CI/CD** (`.github/workflows/ci.yml`) — при каждом сохранении кода на GitHub робот GitHub Actions
  запускает тесты и, если всё хорошо, публикует новую версию сайта.
